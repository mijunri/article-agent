## 数据抓取技术方案

### 目标
- 稳定、可扩展地从多渠道获取热点条目，输出统一 Topic 数据，支撑分析与生成。

### 来源与优先级
- 第一批：Google Trends、Hacker News、主流新闻 RSS。
- 第二批：微博热搜、知乎热榜、B 站热榜。
- 第三批：Twitter/X Trends、Reddit、垂直站点。
- 原则：优先官方 RSS/API；必要时使用 HTML 解析。

### 访问方式与协议
- RSS：优先（低耦合、稳定）；`feedparser` 容错解析。
- API：按官方限制接入，带认证/分页/速率控制。
- HTML：`lxml/BeautifulSoup`；CSS/XPath 定位稳定父容器与锚点；提供 Selector 版本号。

### 反爬与访问控制
- 合规：遵循 Robots 与 ToS。
- Header：自定义 UA；必要时带 Referer/Cookie。
- 代理：支持 IP 代理池（跨境/区域站点）。
- 节流：全局/单源 QPS 限制与令牌桶；突发控制；夜间窗口优先。
- 重试：指数退避（含抖动）；超时/最大重试可配。
- 熔断：单来源连续失败后降级/跳过一定窗口并告警。

### 调度与并发
- 调度：Cron/K8s CronJob（每 10–30 分钟可配）。
- 并发：按来源隔离线程池；限制连接数与并发请求。
- 预去重：请求前基于缓存索引过滤近期 URL/标题。

### 解析与抽取
- 字段：title、url、summary（长度限制）、published（统一 UTC）。
- 清洗：去空白、控制符、常见装饰词；URL 去跟踪参数、统一 scheme、可选解短链。
- 变更监测：选择器命中率异常触发告警与回退（启用上一版本解析器）。

### 规范化与稳定 ID
- 时间：统一 UTC（带 tz）；缺失时用抓取时间。
- 稳定 ID：`hash(source|title|url_or_title)`；算法与长度固定。
- 模型：输出标准 `Topic` 列表。

### 去重策略
- 精确去重：键 `(title_norm, url_or_empty, source)` + 稳定 ID。
- 近似去重（可选）：SimHash/MinHash + Jaccard 阈值；避免同题换标题二次产出。
- 缓存：Redis/SQLite 维护 48h 窗口；命中则跳过生成。

### 质量控制
- 字段完整性校验：必填项与长度/字符集限制。
- 黑白名单：关键词过滤、域名白名单（可选）。
- 抽样审计：每批随机 N 条人工/规则复核。

### 错误处理
- 网络：超时/重试/降级；DNS/TLS 异常分类上报。
- 解析：单条失败不中断批次；错误样本落地便于回归。
- 来源：连续失败熔断并告警；下个窗口再试。

### 存储与产物
- 原始落地（可选）：`raw/{source}/YYYYMMDDHH/`。
- 规范化产出：`topics/YYYYMMDD/*.json` 或直接进入内存队列。
- 索引：SQLite/Redis 记录产出索引、幂等键、窗口缓存。

### 可观测性
- 日志：JSON 结构化，含 source/status/latency/retries。
- 指标：抓取成功率、解析命中率、平均延迟、近似重复率。
- 告警：来源失败、命中骤降、产出为 0、重复率升高。

### 安全与合规
- 仅抓取公开可用信息；引用与版权合规。
- 敏感内容规避；不保存账号敏感凭证。
- 代理与跨境访问合规自查与白名单管理。

### 验收标准与上线
- 验收：稳定抓取 3+ 来源；P95 ≤ 2s/条；成功率 ≥ 98%；Topic 字段完整率 ≥ 99%；重复率 ≤ 1%。
- 上线：影子运行 1–2 天 → 小流量（Top-3）→ 全量（Top-N）；记录指标与问题单，迭代选择器与权重。
